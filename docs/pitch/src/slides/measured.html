MEASURED

SAY (20 seconds): We measured before we tuned. The Buyer used to be a tool loop: about four model calls and 43,500 prompt tokens for one request. Now it is one call and 742 tokens. A ranked prompt and a code guard took exact picks from 27 to 69 out of 90 test replies. And when the kitchen’s own corrections go in as memory, a simulated chef corrects 41 percent less. CUE: none of this is in the demo. It is the answer to NVIDIA’s question "how did you improve its outputs". The demo video says "almost eight times fewer tokens": that is another true pair, 2,251 completion tokens down to 289 on the old loop. SAY THE LIMITS IF ASKED: the calls and tokens are from three live requests per row. The 30-request set is an exploratory development set, not held-out evidence; 54 of 90 is the model alone, and the step to 69 is code. The chef is synthetic and each cell is 8 kitchen-weeks. No fine-tuning: the gate decided no-go.
